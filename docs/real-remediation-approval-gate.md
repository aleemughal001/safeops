# SafeOps Real Remediation Approval Gate

Milestone 24 adds an approval gate between remediation planning and execution.

The approval gate reads the real Kubernetes remediation plan generated by Milestone 23 and creates an approval-ready request package. It can also record a local approve/reject decision for demo and audit purposes.

## Purpose

SafeOps should not jump from diagnosis directly to production changes. A safe workflow requires:

1. real incident detection,
2. grouped evidence pack,
3. remediation plan,
4. human approval,
5. policy validation,
6. controlled execution,
7. verification and audit.

Milestone 24 implements step 4 without executing anything.

## Generated artifacts

Default output files:

```text
/tmp/safeops-demo/real-k8s-approval-request.json
/tmp/safeops-demo/real-k8s-approval-request.md
/tmp/safeops-demo/real-k8s-approval-decision.json
/tmp/safeops-demo/real-k8s-approval-decision.md
```

## Safety boundary

The approval gate is read-only. It records decisions, but it does not execute Kubernetes actions.

Even if a plan is approved, execution remains blocked until a later executor milestone performs policy validation and scoped action execution.

## Demo usage

Request-only mode:

```bash
./scripts/demo_real_approval_gate.sh demo
```

Approve mode:

```bash
./scripts/demo_real_approval_gate.sh demo approve "alice@example.com"
```

Reject mode:

```bash
./scripts/demo_real_approval_gate.sh demo reject "alice@example.com"
```

## Expected behavior

Healthy namespace:

```text
Root incidents detected: 0
Plans generated: 0
Approval requests generated: 0
```

Bad image rollout:

```text
Root incidents detected: 1
Plans generated: 1
Approval requests generated: 1
```

Approve/reject still shows:

```text
Execution allowed by approval gate: False
```

This is intentional. Approval is not execution.
